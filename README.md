# Galgame UI 图片汉化工具

这是一个本地 Windows 桌面工具，用于处理已经从游戏中解包出来的 UI 图片。它不会修改游戏封包，也不会覆盖源图片。

## 当前版本能力

- 受 GalTransl Desktop 启发的深色侧栏、首页统计卡片和独立图片工作台
- 批量导入 PNG、JPG、JPEG、BMP、DDS，保留目录结构、宽高和 Alpha 通道
- 图片资源列表显示异步缩略图，并可按未识别、待翻译、待校对和已校对状态筛选
- 内置 PP-OCRv6 日中多语言本地 OCR，默认离线识别，图片不会上传
- 可选择“本地 + 云端合并”或仅使用云端视觉 API；合并模式按置信度去重并保留双方发现的独立区域
- 大图可自动切成带重叠的 1024px 分块，合并跨分块结果，减少云端模型缩图造成的小字漏识
- 内置 Gemini 3.7 Flash、DeepSeek V4 Flash Vision Exp、DeepSeek V4 Flash/Pro 供应商预设和连接测试
- 识图与翻译完全分离：视觉模型只返回日文原文和版式，独立文本 API 再生成中文译文
- 在没有视觉 API 时，手工框选区域、录入日文，再交给 DeepSeek 翻译
- 当前图片识别、未处理图片批量识别、当前图片翻译、全工程待译文本批量翻译
- 本地翻译记忆：自动收录“已人工校对”的日中对照，翻译前优先复用完全相同的原文
- 可编辑术语表：只把当前翻译批次实际出现的术语发送给 API，统一人名、按钮和专有名词译法
- 每个文字区域独立设置字体、字号、字间距、行距、粗体、阴影、发光、渐变、旋转、竖排和自动缩放
- 文字样式预设库：内置四种常用外观，可保存、覆盖、删除并跨工程一键套用自定义样式
- 选择系统字体，或直接载入未安装的 `.ttf` / `.otf` 字体文件
- 按实际像素宽度自动换行，并避免常见中文标点落在错误行首/行尾
- 蒙版画笔、橡皮擦、内容感知修复、边缘渐变、纯色采样、透明清除和保留原图
- DDS 支持 DXT1/BC1、DXT3/BC2、DXT5/BC3、32 位 BGRA，并保持原压缩类型和 mipmap 数量
- 自动识别 TexturePacker JSON 与 Spine `.atlas`，在画布显示精灵名称和原始边界
- 非破坏性工程文件、效果预览、低置信度标记、人工校对状态
- 可拖动原图对比滑杆，在同一画布左右查看原图与最终汉化效果
- 导出前质量预检：空译文、文字溢出、区域越界、字体缺失、日文残留、占位符/数字变化、术语不一致和未校对提示
- 每张图片导出后自动复开，并验收尺寸、Alpha、DDS 参数、实际像素和汉化区域可见变化
- 30 步撤销/重做、30 秒自动恢复、原子保存和 `.bak` 工程备份
- 完整批量任务中心：逐项状态、暂停/继续、取消、失败重试、清理记录和任务报告
- 批量任务断点自动保存；软件重启后重新打开工程，可继续未完成的识图、翻译和导出任务
- 批量导出并生成 `UI汉化导出报告.txt`

## 直接运行

推荐使用绿色便携版。完整解压后双击：

```text
publish\GalgameUiTranslator-v0.9.1-portable\GalgameUiTranslator.exe
```

也可以把 `GalgameUiTranslator-v0.9.1-portable.zip` 复制到其他 64 位 Windows 电脑，完整解压后运行；无需单独安装 .NET。不要只复制 EXE，必须保留旁边的 `.runtime` 和 `models` 文件夹。

开发目录内也可直接双击：

```text
publish\GalgameUiTranslator-net10-framework\GalgameUiTranslator.exe
```

程序会通过内置相对路径使用工程目录中的 `.dotnet10`。不要只移动 `.exe`；可为该文件创建桌面快捷方式。

## 推荐流程

1. 点击“打开图片文件夹”，选择解包后的 UI 图片根目录。
2. 点击“API设置”，选择视觉与翻译供应商预设并测试连接；只离线识图时可保留“本地 OCR”。
3. 点击“识图”离线识别日文；装饰字或漏识内容可点击“框选”，手工建立区域并填写日文原文。
4. 在“术语库”中录入固定译法，再点击“翻译”或“批量翻译”；完全相同的已校对原文会先从翻译记忆回填。
5. 逐个检查译文与区域尺寸；在右侧“文字样式预设”中套用常用外观，或把当前外观保存为跨工程预设。
6. 复杂背景选中文字区域后，用“蒙版笔/蒙版擦”准确覆盖原文字，再选择“内容感知修复”。
7. DDS 或图集图片可打开“图集框”核对精灵边界；软件不会重新排布图集坐标。
8. 打开“原图对比”并拖动蓝色分界线检查修图效果，然后运行预检；从批量任务中心观察导出、暂停或重试失败项。
9. 保存 `.guih.json` 工程，导出到不同于源目录的位置，再使用原工具回封。

鼠标滚轮缩放画布，中键拖动平移；拖动文字框可移动，拖动右下角可改变大小。`Ctrl+S` 保存工程，`Delete` 删除选中的文字区域。

## API 配置

文本翻译默认配置为：

```text
API 地址：https://api.deepseek.com
模型：deepseek-v4-flash
```

模型名称可在设置中修改。默认使用 Windows 凭据管理器按供应商分别保存 API Key：DeepSeek、Gemini 和各个自定义接口互不覆盖；识图与翻译使用同一供应商时自动共用密钥。密钥不会写入工程、`settings.json` 或任务恢复文件。取消“保存 API Key”后，密钥只在当前进程内使用，也可随时清除当前供应商的已保存密钥。

视觉识别可直接选择 `DeepSeek V4 Flash Vision Exp（实验）` 或 `Gemini 3.7 Flash（视觉）`。DeepSeek 视觉模型属于实验接口，输出稳定性可能变化；本地 OCR 始终可作为不上传图片的保底方案。Gemini 与 DeepSeek 都通过各自的 OpenAI 兼容入口调用，软件会自动采用对应请求参数。

视觉 API 与文本翻译 API 完全分开。视觉模型的输出不会直接写入译文；翻译记忆命中或独立文本翻译完成后才会填写中文。这样更换视觉模型不会覆盖已经校对的译文。

## 本地 OCR 与隐私

- 默认模式使用随便携版提供的 PP-OCRv6 检测与识别模型，不需要识图 API Key。
- “本地 OCR”模式不会上传图片；DeepSeek 只接收识别出的文本。
- “本地 + 云端合并”会把每张待识别图片上传到云端；启用大图分块时一张图片可能产生多次请求，软件会在批量处理前明确提示。
- OCR 模型位于 `models` 文件夹，缺失时软件会停止识图并显示缺少的文件名，不会静默改用云端。
- 自动识别结果仍需人工校对，尤其是艺术字、竖排文字、小字号和低对比度内容。

## 翻译记忆与术语表

- 勾选文字区域的“已人工校对”后，日文原文和中文译文会自动写入本地翻译记忆。
- 再次遇到完全相同的日文时，软件会先从记忆回填；只有未命中的内容才调用翻译 API。
- 重新编辑原文或译文会自动取消“已人工校对”，避免未确认内容污染记忆。
- 术语表适合固定人名、地名、系统按钮和游戏专有名词。API 请求只携带当前批次中实际出现的术语。
- 翻译记忆和术语表保存在当前 Windows 用户的本地应用数据目录，不写入游戏工程，也不包含 API Key。

## 文字样式预设

- 右侧属性区的“文字样式预设”提供“应用、保存/覆盖、删除”操作。
- 预设包含字体、字号、粗体、自动适配、文字/描边颜色、间距、阴影、发光、渐变、旋转、竖排和对齐方式。
- 预设不会修改日文原文、中文译文、文字框坐标、人工校对状态、修复蒙版或背景清除方式。
- 内置“白字黑描边、标题金色渐变、黑字浅色面板、霓虹蓝发光”四种常用样式。
- 套用到当前区域后，仍可点击“将当前字体和样式应用到本图全部区域”完成整张图片的统一排版。
- 自定义预设保存在当前 Windows 用户的本地应用数据目录，可在其他工程继续使用。

## 背景模式

- `内容感知修复`：从蒙版边缘逐层重建颜色，适合不规则文字笔画和简单纹理。
- `边缘渐变修补`：从文字框四周插值重建背景，适合渐变按钮和简单底图。
- `边缘纯色采样`：使用边缘平均色填充，适合纯色面板。
- `清为透明`：适合文字直接绘制在透明图层上的资源。
- `保留原图`：不清除原文字，适合只调整排版或测试文字效果。

复杂纹理、文字压住人物或装饰图案时，先用蒙版缩小修改范围；本地内容感知算法仍不等同于生成式 AI 局部重绘。

## DDS 与图集

- DDS 导出保持原宽高、BC1/BC2/BC3 或 BGRA 格式以及 mipmap 层数。
- BC7、立方体纹理、体积纹理和数组纹理会明确拒绝，不会静默写坏。
- TexturePacker JSON 和 Spine `.atlas` 会自动绑定到同目录对应图片。
- 图集始终按完整原画布编辑和导出，因此精灵坐标不会变化。

## 批量任务中心

顶部的“批量识图”“批量翻译”和“导出”会创建逐项任务并自动进入任务中心。暂停会在当前单项完成后生效；取消会保留已经完成的结果。失败项可直接重试，也可保存文本报告。

任务队列和每个已完成单项的工程结果会写入当前 Windows 用户的本地恢复目录。批量任务运行时退出，软件会保存断点；下次恢复或打开同一工程后，在任务中心点击“继续未完成”即可续跑。API Key 不会写入恢复文件；启用 Windows 凭据管理器保存后，软件会按供应商自动读取，否则需要重新填写。

## 当前限制

- 尚未支持 BC7 DDS、PSD、WebP、Unity SpriteAtlas 或游戏封包。
- 图集元数据目前支持 TexturePacker JSON 与 Spine `.atlas`；不负责修改元数据或重新排布精灵。
- 本地 OCR 与视觉模型给出的文字和坐标都可能不精确，导出前必须人工预览。
- 自动质量检查能发现结构性错误和明显像素异常，但不能代替对语义、艺术字效果和游戏内实际显示的人工验收。
- 本地内容感知修复适合文字笔画和简单纹理，复杂人物或装饰仍可能需要外部修图。

## 构建与测试

安装项目本地 .NET 10 SDK 并生成默认可运行版本：

```powershell
.\install-dotnet10-local.ps1
.\build-net10-release.ps1
```

完成后文件位于 `publish\GalgameUiTranslator-net10-framework\GalgameUiTranslator.exe`。它会使用项目根目录的 `.dotnet10`。

同一构建命令还会生成可独立复制的绿色便携目录和 ZIP：

```text
publish\GalgameUiTranslator-v0.9.1-portable\
publish\GalgameUiTranslator-v0.9.1-portable.zip
```

网络可访问 NuGet 时，可额外生成自包含单文件版本：

```powershell
.\build-net10-release.ps1 -SelfContained
```

输出位于 `publish\GalgameUiTranslator-net10-win-x64\GalgameUiTranslator.exe`。

重新构建发布目录：

```powershell
.\build-release.ps1
```

运行烟雾测试：

```powershell
$env:DOTNET_CLI_HOME=(Join-Path (Get-Location) '.dotnet-home')
.\.dotnet10\dotnet.exe restore tests\SmokeTests\SmokeTests.Net10.csproj --configfile NuGet.Net10.Config
.\.dotnet10\dotnet.exe run -c Release --project tests\SmokeTests\SmokeTests.Net10.csproj --no-restore
```
